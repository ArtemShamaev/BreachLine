# Breachline WEB

Браузерный тактический шутер 5×5 с ботами, русским и английским интерфейсом, сохранениями, аккаунтами и LAN.

## Запуск

Нужен Node.js 18 или новее. Зависимостей сервера нет.

```sh
npm start
# либо другой порт:
node server.js 8090
```

Откройте **http://localhost:8088/**. Сервер напечатает адреса для других компьютеров локальной сети. Порт можно задать через `BREACHLINE_PORT` или `PORT`.

Одиночная игра работает и на статическом хостинге; аккаунты и LAN требуют Node.js-сервер. Рядом с `index.html` должны находиться `game.js` и `i18n.js`.

## Язык и аккаунты

Переключатель «Язык / Language» находится сверху главного меню. По умолчанию выбран русский, выбор сохраняется в браузере.

В разделе «Аккаунт» есть вкладки «Вход» и «Регистрация»; войти можно с любого компьютера, открывшего **тот же сервер**. Аккаунт необязателен для одиночной игры и LAN.

- Имя: 3–24 буквы, цифры, `_` или `-`, без смешения латиницы и кириллицы (чтобы «Аdmin» с русской «А» не выдавал себя за «Admin»). Регистр не важен: «Игрок» и «игрок» — одно имя.
- Пароль: 8–128 символов, не содержит имя. Хранится как scrypt-хеш с индивидуальной солью.
- Сессия живёт 30 дней с продлением при использовании и **переживает перезапуск сервера**. В HttpOnly-cookie лежит случайный токен, на диске — только его SHA-256.
- После входа доступны: «Выйти», «Выйти на других устройствах», «Сменить пароль» (завершает все остальные сессии) и «Удалить аккаунт» (вместе с серверным сохранением, требует пароль).
- Защита от перебора: после 10 неверных паролей вход в это имя блокируется на 15 минут; с одного IP — не более 30 попыток входа за 10 минут и 10 регистраций в час. На Render реальный IP берётся из `X-Forwarded-For`; на другом хостинге за прокси задайте `BREACHLINE_TRUST_PROXY=1`.
- В LAN-матче имя вошедшего игрока подтверждает сервер, поэтому выдать себя за чужой аккаунт нельзя. Гости без аккаунта играют под своим ником.

Аккаунты прежней версии (файлы `data/<хеш>.json`) переносятся автоматически при первом запуске; пароли и сохранения сохраняются, старые файлы перемещаются в `data/legacy-v1/`.

## Сохранения

- «Сохранить матч» в меню Esc создаёт снимок текущего матча.
- Автосохранение срабатывает каждые 15 секунд и при выходе в главное меню.
- «Продолжить сохранение» восстанавливает карту, раунд, счёт, позиции, здоровье, оружие, деньги, гранаты и бомбу.
- У гостя сохранение находится в браузере. У аккаунта есть также серверная копия; при входе выбирается более новая копия.
- Один слот на аккаунт и отдельный гостевой слот. Новый матч заменяет старое сохранение при следующем сохранении.
- Сетевой матч сохраняет ведущий. При восстановлении он становится одиночным матчем, места остальных людей занимают боты. Гости не сохраняют чужой матч.

Сервер хранит данные в `data/`: `accounts.json` (аккаунты и сессии) и `saves/` (сохранения); папка не публикуется по HTTP и исключена из Git. Другую папку задаёт `BREACHLINE_DATA`. Для переноса или резервного копирования сохраните всю папку. При размещении на хостинге подключите постоянное хранилище и направьте `BREACHLINE_DATA` в него: локальная файловая система временного контейнера не переживает пересоздание контейнера.

## LAN

1. На одном компьютере запустите сервер. Все компьютеры должны находиться в одной локальной сети; разрешите входящие соединения на выбранный порт.
2. На каждом компьютере откройте **один и тот же адрес**, напечатанный сервером, например `http://192.168.1.21:8088/`.
3. Ведущий выбирает карту, сторону, сложность и длительность, открывает «Игра по локальной сети», задаёт код и нажимает «Создать комнату».
4. Остальные выбирают сторону, вводят ник (или входят в аккаунт), тот же код комнаты и нажимают «Подключиться», затем «Продолжить».

До **10 игроков**, по пять на сторону. Люди занимают места ботов; при заполненной выбранной стороне игрок попадает на другую. При отключении гостя его заменяет бот. При выходе ведущего комната закрывается. Пауза открывает настройки, но не останавливает сетевой матч. Ведущий может начать следующий матч кнопкой «Новый матч».

Сервер передаёт WebSocket-сообщения, а браузер ведущего рассчитывает движение, попадания, покупки, бомбу и результаты. Гости передают управление и получают общий снимок примерно 20 раз в секунду. Ведущий должен держать браузер запущенным; спящий компьютер не может вести матч. Это реализация для доверенной локальной сети, без соревновательного античита. Протокол и устройство ретранслятора основаны на соседнем проекте Barnocraft-WEB.

## Проверка

```sh
npm test
```

Тесты проверяют регистрацию и правила имён, вход, сессии после перезапуска, смену пароля, удаление аккаунта, перенос старых аккаунтов, защиту от перебора, изоляцию сохранений, HTTP-доступ к файлам и жизненный цикл LAN-комнат. Для ручной проверки откройте игру в двух браузерах или на двух компьютерах, создайте комнату, подключитесь, проверьте движение, стрельбу, покупки и выход. `test/browser.cjs` содержит дополнительную проверку Firefox через Puppeteer (инструмент устанавливается отдельно).

`render.yaml` запускает Node.js-сервис вместо прежнего статического сайта.
